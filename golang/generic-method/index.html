Generic Method について

Tags: #generics #golang #language #programming
 :      
History in GitHub Page

先日行われた『実用 Go言語 第2版』の読書会で

という記述に対して，実は Go 1.27 から Generic Method がサポートされたんだよん，という雑談に発展した。 この記事では，遅ればせながら，復習がてら Go 1.27 で導入された Generic Method について解説する。

Go 1.27 より前の Generics

せっかくなので『実用 Go言語 第2版』のサンプルコードを例に書いていこう。

たとえば，数値型 T の値の平均値を取る Average[T]() 関数を定義するとこんな感じになる。

えーっと。 コードに対するツッコミはなしで1。 私が書いたわけじゃないし（笑）

別の実装として，型に対しても型パラメータを指定できる。

Average[T] 型では Add(T) メソッドで値を加えていって Result() メソッドで結果を取り出す構成になっている（コードに対するツッコミはなしでw）。 ここで Add() メソッドの引数には T 型とは異なる数値型を指定し，内部でキャストして加算したいところであるが，1.27 より前では Average[T] 型の型パラメータは T の制約に縛られているため，メソッドでそれ以外の型パラメータを追加することはできない。 どうしてもキャストして加算したいのであれば，専用の Generic 関数を用意する。

ただ，この方法だと Generic 型に関連する Generic 関数が山ほど生えてくる可能性があり，特にコンテナ操作に関してはパッケージの構成が煩雑になると思われる。 記述自体も煩雑になりがちだし。

こういった理由で，メソッドに独自の型パラメータを追加できるようにして欲しいという要望が多かったようだ。

Go 1.27 の Generic Method

そこで Generic Method の登場である。 前節の Average[T] 型を Generic Method を含む形に書き換えてみよう。

package main

import (
	"fmt"
	"math"
)

type Average[T int | float64] struct {
	total T
	count int
}

func (a *Average[T]) Add[U int | float64](v U) *Average[T] {
	a.total += T(v)
	a.count += 1
	return a
}

func (a *Average[T]) Result() T {
	if a.count == 0 {
		// When T is int, the result of converting NaN to an integer is implementation-specific.
		return T(math.NaN())
	}
	return a.total / T(a.count)
}

func main() {
	fmt.Println("Average:", (&Average[float64]{}).Add(1).Add(2.0).Add(4).Result())
	// Average: 2.3333333333333335
}

オリジナルから少し細工をしてAdd[U]() メソッドを連結して記述できるよう返り値を自身のポインタにしている。 main() 関数では Average[float64] 型のインスタンスを生成し 1, 2.0, 4 と値を追加して平均値を取り出している。

Generic Method の制約

Generic Method は interface のメソッドとして宣言できない。 たとえば

type MyInterface interface { // interface type with generic method (not allowed)
	DoSomething[T any]()
}

と書いても “interface method must have no type parameters” というコンパイルエラーになる。

それじゃあ，というので interface 型のメソッド定義から型パラメータを外した上で

type MyInterface interface { // interface type with non-generic method
	DoSomething()
}

type MyStruct struct{} // concrete type implementing MyInterface

func (m *MyStruct) DoSomething[T any]() { /* ... */ }

func New() MyInterface {
	return &MyStruct{} // compile error due to signature mismatch
}

と書いても，interface 型と concrete 型の間でシグニチャが合わないため，以下のエラーになる。

cannot use &MyStruct{} (value of type *MyStruct) as MyInterface value in return statement: *MyStruct does not implement MyInterface (wrong type for method DoSomething)
		have DoSomething[T any]()
		want DoSomething()

interface 型のメソッドとして Generic Method を許すと，インターフェース値を介した呼び出しで実行され得る具象メソッドを一般には特定できず，必要な型引数の組み合わせをコンパイラがあらかじめ展開するのが難しい。

というわけで interface 型のメソッドでは Generic Method を使えなくしているようだ。

Generic Method を使った実装

Go 1.27 の math/rand/v2 パッケージでは，Generic Method を使った乱数生成が可能になっている。

package main

import (
	"fmt"
	"math/rand/v2"
)

func main() {
	rng := rand.New(rand.NewPCG(1, 2))
	for i := range 5 {
		fmt.Println(i+1, rng.N[int64](100)) // generate a random int64 number less than 100
	}
}

またサードパーティでは，以下のパッケージが Generic Method を使った実装を提供しているようだ。

  • ahmetb/go-linq: .NET LINQ capabilities in Go
  • goforj/collection: Fluent generic Go collections for explicit slice pipelines, transformations, filtering, aggregation, and collection helpers. : v4 以降
  • grandper/go-monad: A monadic types library for Go, providing Option, Result, Either, Promise, Lazy and IO monads with full Map, FlatMap, and Fold support.
