eMudhra 中間 CA 鍵の危殆化

eMudhra は，インドを拠点にデジタル ID や電子証明書，PKI などの事業を行う企業グループだそうな1。 証明書発行事業を担う会社は eMudhra Limited で，インド認証局監督機関（Controller of Certifying Authorities; CCA）のライセンスを受けているようだ。

先日の中間 CA 証明書の秘密鍵の危殆化（compromise）と，それに伴うルート CA 証明書の失効に関する情報については，以下が参考になる。

  • eMudhra Statement on Recent Certificate Security Incident
  • 2083449 - eMudhra: Private key compromise of Intermediate Certificates

どうやら，クライアント側で中間 CA 証明書を個別に失効させられない場合に備えた予防措置としてルート CA 証明書も失効することにしたらしい。 主要ブラウザでは既にルート CA 証明書が失効しているはずである。 ただし，独自に CA 証明書をバンドルしているアプリケーション，コンテナ，VPN，組込み機器などは，個別の対応が必要になる。

今回の危殆化に至る経緯が明らかになるにつれ（かなり間抜けだったらしい），同社に対する批判が高まり，グローバル SSL/TLS 証明書事業から段階的に撤退することにしたようだ。

他のインド国内向けの事業については継続するとのこと。

Go の対応

今回の件に対応するため Go 1.27.3 がリリースされた。 経緯や対応については，以下の公式ブログ記事が参考になる。

  • Our Response To The eMudhra Key Disclosure Incident - The Go Programming Language

Go は標準ライブラリに TLS 証明書の検証機能を持っている。 Windows と macOS では検証を OS の API に移譲しているが Linux では独自実装の検証器を用いている。

というわけで Web や gRPC など TLS 接続を行うネットワークサービスにアクセスする可能性のある Go 製ツールは，Go コンパイラを 1.27.3 (または 1.26.10) 以降に更新してビルドし直す必要がある。

Go 以外の製品の情報については次節のブックマークを参照のこと（随時更新予定）。 まぁ，証明書の危殆化はビックリするほど珍しいことではないので（多くはないが過去にも危殆化事例はある），粛々と対応するのが吉である。
